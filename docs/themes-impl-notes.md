# Themes implementation notes

Built per docs/plan-themes.md (all section 8 / 8b decisions). Not committed.

## What was built
- `static/themes.css` (new, linked before `style.css`): shared `:root` (radii, tabbar height, `--media-*` constants) + five token blocks selected by `[data-theme="default|dark|ember|tide|graphite"]` (default also on `:root`). Each block has `color-scheme` and `--meta-theme-color`. Blocks match on the attribute alone, so the picker mini previews reuse them via `data-theme` on any element.
- `static/style.css`: all colour literals replaced by tokens (grep for `#hex`/`rgba(` in declarations is clean; enforced by a test). Second `:root` removed. Teal Classic refinements applied (`--muted`, `--placeholder`, `--input-border`, `.error`/`.server-error` use `--danger-text`). New block at the end: global `:focus-visible` (2px `--focus`), image filter (`--img-filter`) + 1px outlines on thumbs, autofill fix, 200 ms switch transition (`html.theme-switching`, off for reduced motion), icon cues, picker styles, `forced-colors`.
- `index.html`: blocking inline boot script before the stylesheets (same logic as ThemeCore.resolve), `<meta name="color-scheme" content="light dark">`, `theme-color` default `#f4f6fb`, favicon links, hidden SVG `<symbol id="logo">`, header mark and login hero use it, theme picker in Profile.
- `static/theme-core.js` (pure, Node-testable) and `static/theme.js` (runtime): `Theme.get() / set(pref) / list() / resolved() / onChange(fn)`; `themechange` event on `document`; OS change listener (only while pref is `auto`); `storage` event sync between tabs; localStorage key `innodigym_theme` (`auto|default|dark|ember|tide|graphite`, invalid/missing -> `auto`, no API call).
- `static/i18n.js`: ES strings for the picker (names translated: Teal clásico, Medianoche, Brasa, Marea, Grafito; plus `Theme: {name}`). Static picker text is translated by the existing static pass. Key-coverage scan of every `t("...")` and index.html text/attrs: all covered (only the brand name, `&larr;` entities and the language names are intentionally absent).
- Non-colour cues: CSS-mask icons via `::before` on `.pl-note` (info), `.pl-note.warn` (triangle), `.error`, `.server-error`, non-empty `.err` incl. error toast (x-circle) and non-empty `.ok` (check-circle). No JS/markup change needed.
- Logo: traced from the owner's PNG with OpenCV (threshold, connected components, contours, simplified polygons; no potrace available). Two even-odd paths in `<symbol id="logo" viewBox="0 0 96 96">`: `.logo-machine` (fill `--logo-machine`, opacity `--logo-machine-op`) and `.logo-figure` (fill `--logo-figure`); both default to `currentColor`. Header mark: single colour `--brand-fg` on the gradient tile, machine at .78 opacity so the figure reads at 30 px. Login `.logo-hero` (88 px): figure `--primary`, machine `--text`. White cut-lines are real gaps in the paths, so no `--logo-cut` needed. Files: `favicon.svg` (own colours, dark variant via `prefers-color-scheme` inside), `favicon-32.png`, `apple-touch-icon.png` (180, opaque), `icon-192.png`, `icon-512.png` (for a future manifest; none added). The `DUMBBELL` placeholder in courses.js/movements.js is untouched.

## DOM
Picker: `fieldset#theme-picker.theme-picker` > `div.theme-grid[role=radiogroup]` > 6 `label.theme-card` (`input[type=radio][name=theme][value=...]`, `.theme-mini[data-theme]` (aria-hidden), `.theme-name`, `.theme-desc`); `.checked` class synced by JS; `#theme-live` sr-only aria-live announcement ("Theme: Midnight"). Auto card: `.theme-mini-auto` with two `.tm-half` (default + dark, diagonal clip).

## How to test
- `node --check static/*.js && node --test static/*.test.js` (new: `theme-core.test.js`: resolution, invalid values, every theme has block/picker card/boot entry, meta colour == `--bg`, identical token sets, no colour literals in style.css).
- Browser: Profile tab > pick a theme (instant, no network call; reload keeps it); DevTools `localStorage.innodigym_theme = "ember"` + reload (no flash); DevTools rendering emulation prefers-color-scheme with Auto switches live.
- Screenshots (stubbed fetch, isolated context) in `qa/screens/themes-*.png` (login x5 at 375, dark editor, 320 ES profile).

## Known gaps
- The numeric contrast script (`scripts/check-theme-contrast.js`, plan 5.6 step 8) was not written; contrast values are from the plan only. Real photo data in dark (glare of white PNGs) and Windows forced-colors were not tested on real hardware. Colour-blind emulation pass not done.
- Not every screen was screenshotted for all five themes (login all five; other screens checked in Midnight, Ember, Graphite; Plans wizard step 3 / action picker not visually checked with real data).
- `.mv-ph` / placeholder icons still use `--border-strong` (low but decorative in dark).
- No web-app manifest (PNG icons exist for it). `meta theme-color` is ignored by some desktop browsers.
- Graphite login: figure and machine are both near-black (primary = text), so the two-tone effect is minimal there.
- Header "Log out" wraps to two lines at 375 px (pre-existing layout, not touched).

## Seasonal themes (FitMas/HallowFit)
Themes `fit-xmas` (light) and `hallowfit` (dark) are normal themes in `themes.css` plus an optional decoration layer. Colours and fonts always apply; only the decoration layer is controlled by the Full / Subtle / Off setting (`innodigym_fx`, Profile "Seasonal decorations"). Nothing here is ever chosen by Auto.
- `static/theme-fx-core.js` (pure, Node-tested): `THEMES` that have a layer, `normalizeMode`, `effective(setting, {theme, reducedMotion, saveData})` (reduced motion and data-saver cap Full at Subtle; a theme without a layer is Off), `particleCount`.
- `static/theme-fx.js`: runtime. Creates `#fx-root` (aria-hidden, `pointer-events: none !important`) with two layers: `.fx-back` (z-index -1, behind content) and `.fx-front` (z-index 35, above content, below tab bar 40, modals 50+, lightbox 60, toast 80). Sets `html[data-fx=full|subtle|off]`, mounts/unmounts the per-theme handler on `themechange`, setting change, reduced-motion change and `storage` events (other tabs), toggles `html.fx-paused` on hidden tabs. API: `ThemeFx.register(themeId, {mount(ctx), unmount()})`, `get/set/mode/onChange/inline(name)` (fetches `fx/art/<name>.svg` once).
- `static/theme-fx.css`: overlay, layer z-indexes, Subtle (all animation off), paused, reduced motion, forced-colors/print hide, the Profile segmented control.
- `static/theme-fx-xmas.js/css`: light string (4 stacked layers, opacity twinkle), snow canvas (body level, rAF, 33 ms cap on narrow screens, frame-cost guard that freezes it as `xmas-static`), logo sparkles/shooting star, CSS-only art as data URIs (snow lips, header icicles, logo Santa hat, Profile ornaments).
- `static/theme-fx-halloween.js/css`: webs, fog, eyes, spiders, ghost, jack-o-lantern, bats, logo bat, scuttle spider, card web + first-card pumpkin; timers all go through one `later()` set that `teardown()` clears.
- Art lives in `static/fx/art/*.svg` (README lists tokens). Colours come from `--fx-*` tokens declared per theme (`html[data-theme="fit-xmas"]` in `theme-fx-xmas.css`, `hallowfit` in `theme-fx-halloween.css`); SVG fallbacks only matter when inlined without the theme. `theme-fx-css.test.js` fails if a token used by the art is not declared.
- Lite mode: on data screens the layer calms down. FitMas `html.xmas-lite` (Plans, Actions, History, Fitness, Programs editor): snow canvas hidden, rAF stopped, twinkle and star off. HallowFit `html.hf-lite` (Plans, History, Fitness, editor): bats/scuttle/fog drift stop, spiders hang still. Both observe the `hidden` attribute of the tab panels (real tab clicks).
- Rules for CSS in this layer: never put `::before/::after` inside `:is()`; animation overrides of higher-specificity theme rules need `!important`; anything drawn outside `#fx-root` (canvas, `.xmas-top`, logo bat, card/header pseudo-elements) needs its own `forced-colors`/print hide and `aria-hidden`.
- Easter eggs: tap the logo (FitMas: sparkle burst; HallowFit: ghost says Boo, logo bat flaps away), occasional shooting star (FitMas), spider trips / bat / scuttle (HallowFit). Full mode only.
- Add a new seasonal theme: add its block to `themes.css` (+ picker card, boot list, `theme-core.js` ids as for any theme); add the id to `THEMES` in `theme-fx-core.js`; create `theme-fx-<name>.js` (call `ThemeFx.register(id, {mount, unmount})`, build into `ctx.back/ctx.front`, tear down everything in `unmount`) and `theme-fx-<name>.css` (declare `--fx-*` tokens under `html[data-theme="<id>"]`, honour Subtle via `theme-fx.css`, add forced-colors/print rules for anything outside `#fx-root`); link both in `index.html`; add art to `static/fx/art/`; extend the tests.
- Disable: user: Profile > Seasonal decorations > Off (per device) or the OS reduced-motion setting (Subtle). Globally: remove `fit-xmas`/`hallowfit` from `THEMES` in `theme-fx-core.js` (layer never mounts; the themes keep their colours), or unlink the `theme-fx*.js` files in `index.html`.
- QA: `qa/themes-seasonal-test-plan.md`, `qa/themes-seasonal-report.md`, helpers `qa/seasonal-*.js`.
